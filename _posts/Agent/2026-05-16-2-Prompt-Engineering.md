# 提示词工程

## 前Agent时代

在Agent概念火起来之前，我们只有一个接口控制LLM——写提示词。

> 那时候的“炼丹术”，现在看有点原始，但思想都沉淀到Agent框架里了。

### 一、基础技巧：控制“怎么输出”

#### 1. Zero-shot（直接问）

也就是把 LLM 当聪明人，能理解我们的问题，直接问问题。

> **冷知识**：Zero-shot对GPT-3.5以上模型才真正好用。早期GPT-2时代，Zero-shot基本是灾难。

#### 2. Few-shot（给几个例子）

在问题前面塞几个“问题-答案”对作为实例，让模型照着示例的格式回答问题。

> **冷知识**：例子的顺序会影响结果。把难的例子放前面，简单的放后面，效果更好。这叫“由难到易”编排法。

#### 3. Role Prompting（角色扮演）

让LLM穿上特定制服，激活训练数据里对应角色的说话方式以及相关知识。

> **冷知识**：给角色加“人格细节”效果更好。比如“你是一个脾气暴躁的老程序员，讨厌废话”比单纯说“你是一个程序员”更有用。细节越多，角色越“立得住”。

### 二、高级推理技巧：控制“怎么想”

#### 4. Chain-of-Thought（一步步想）

让模型在给出答案前，先把推理步骤写出来。后来逐渐演变为模型后训练的一个阶段，即训练 LLM 的深度思考能力（Deepseek）

> **冷知识**：即使你在提示词里告诉大模型 “请你一步步思考”，不要求它真的严谨推理，准确率也会提升。玄学，但有效。

#### 5. Self-Consistency（多投几票）

同一个问题问N次，选出现次数最多的答案。

> **冷知识**：有时候让模型“快速直觉”回答然后投票，比让它“一步步想”一次更准。因为一步步想的过程中，模型可能会自己把自己绕晕。

**代价**：贵N倍（N次调用）

#### 6. Tree-of-Thoughts（多条路探索）

不只走一条推理链，而是在每个分叉点都探索多个可能。然后每条路往下走几步，最后选最优路径

> **冷知识**：Tree-of-Thoughts本质是“让LLM自己做个小型MCTS（蒙特卡洛树搜索）”。论文作者承认，这个灵感来自AlphaGo

但是代价是非常贵，在实际产品中只有高价值问题才舍得用。现在被内化进 Agent 规划器和推理时扩展了。

#### 7. Graph-of-Thoughts（网状推理）

Tree-of-Thoughts 的升级版。树不能有回路，图可以——允许不同分支合并、交叉引用。

**例子**：
思路A发现“需要用户数据”，思路B发现“需要调API”，这两个思路可以合并成“先调API拿数据，再分析”

> **冷知识**：Graph-of-Thoughts 是 2023 年中才提出的，火得快凉得也快，因为 Agent 框架直接把这个能力内置了——你不需要手动设计图，Agent自己会决策。

#### 8. ReAct 

在 2022 年的时候，社区有人发明了一段及其精妙的提示词模版，长下面这样：

```plaintext
Question: 美国开国总统是谁？
Thought 1: 我需要查找美国开国总统的信息。
Action 1: Search[美国开国总统]
Observation 1: (这里留白，等开发者把搜索引擎的结果填进来)
Thought 2: 搜索结果是乔治·华盛顿。
Action 2: Finish[乔治·华盛顿]
```

大模型根本不知道什么是“Action”，什么是“Observation”。它只是在做高级的“文字接龙”游戏——
它看到 Thought 1，就顺理成章地编造出 Action 1；它看到 Observation 1 被填入了真实信息，
就顺理成章地推导出 Thought 2。

### 三、一张表总结

| 技巧                | 本质    | 一句话记       | 代价     |
|:------------------|:------|:-----------|:-------|
| Zero-shot         | 直接问   | “把AI当聪明人”  | 无      |
| Few-shot          | 给例子   | “照葫芦画瓢”    | 多写几个例子 |
| Role Prompting    | 穿制服   | “你是XXX”    | 无      |
| Chain-of-Thought  | 写步骤   | “一步步想”     | 输出变长   |
| Self-Consistency  | 多投几次票 | “问多次，选最多”  | 贵N倍    |
| Tree-of-Thoughts  | 多路探索  | “每条路都走走看”  | 很贵     |
| Graph-of-Thoughts | 网状连接  | “路可以交叉”    | 非常贵    |
| ReAct             | 文本控制流 | 实现了一套提示词框架 | 无      |


### 四、这些技巧后来去哪儿了？

Agent时代之后，它们没有被淘汰，而是**被吸收进了框架**：

- **Role Prompting** → 变成了System Prompt + 多Agent角色分工
- **Few-shot** → 变成了“工具使用示例” + 向量库检索示例
- **Chain-of-Thought** → 变成了Agent的“思考-行动-观察”循环
- **Self-Consistency** → 变成了“自我反思” + 多路径探索
- **Tree/Graph-of-Thoughts** → 变成了Agent的规划器（Planner）
- **ReAct** → 变成了 Agent 的 ReAct 架构

**一句话**：前Agent时代，你手动写这些技巧；Agent时代，框架帮你自动执行这些技巧。

### 五、一个值得记住的“神总结”

> “提示词工程是Agent的‘史前史’。
> 
> 那时候我们只有一根棍子（prompt），却想撬动地球。
> 现在我们有了工具箱（Agent框架），但棍子依然在里面——只是你不再需要徒手挥舞它了。”

### 六、冷知识合集（面试时随口抛一个）

1. **例子顺序影响结果**：难的放前面，简单的放后面，Few-shot效果更好。

2. **角色越具体越有效**：“你是一个脾气暴躁、讨厌废话、用Vim不用IDE的10年老程序员” > “你是一个程序员”

3. **Self-Consistency有时比CoT准**：因为强迫模型写步骤可能引入错误，而“直觉投票”保留了隐性推理。

4. **Tree-of-Thoughts的灵感来自AlphaGo**：本质是MCTS的思想移植到LLM推理上。

5. **Zero-shot对GPT-2是灾难**：直到GPT-3.5，Zero-shot才真正好用。这说明“模型足够大”是提示词技巧生效的前提。
