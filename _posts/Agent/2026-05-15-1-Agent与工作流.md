# 工作流与智能体

工作流：通过预定义代码路径来协调 LLM 和工具的系统；

智能体：LLM 动态地指导自身流程和工具使用，自主控制任务完成方式。

## 一句话秒懂

> **工作流是“照着剧本演”，智能体是“即兴发挥，目标自定”。**

另一个版本：**工作流做“判断题和计算题”，智能体做“选择题和作文题”。**

## 核心区别（面试官想听的）

| 维度     | 工作流                     | 智能体                          |
| :------- | :------------------------- | :------------------------------ |
| 决策方式 | 确定性、被动，按预设逻辑走 | 概率性、主动，LLM推理决定下一步 |
| 路径     | 固定，像火车轨道           | 动态，像旷野开车                |
| 目标     | 完成第3步                  | 解决某类问题                    |
| 错误处理 | 只有提前写好的分支         | 可以自己分析失败，换条路走      |
| 成本     | 几乎免费，毫秒级           | 每次调用LLM，几秒到几十秒       |
| 可靠性   | 100%可预期，好调试         | 可能幻觉、循环、难复现          |

## 面试官问这个，到底想考什么？

他绝对不是想听你背定义。他想看你四个层次的能力：

**第一层（及格）**：能说清楚“工作流固定，智能体灵活”

**第二层（良好）**：能给例子——什么场景用工作流，什么场景用智能体

**第三层（优秀）**：知道权衡——智能体贵、慢、不确定，能用工作流就别炫技

**第四层（卓越）**：有批判思维——智能体目前不成熟，有幻觉和可控性问题，别盲目追热点

## 一个真实例子：客服工单自动处理

场景：电商每天上千条工单，要判断类型、提取信息、执行操作、回复用户。

我的拆解：

| 子任务                  | 选谁   | 为啥                                   |
| :---------------------- | :----- | :------------------------------------- |
| 意图分类                | 智能体 | 用户说话千奇百怪，规则写不完           |
| 提取订单号/商品名       | 工作流 | 正则搞定，便宜又快速                   |
| 调用API（创建退货单等） | 工作流 | 输入输出固定，要可靠执行               |
| 异常情况处理            | 智能体 | 比如订单不存在、用户骂人，没法提前枚举 |
| 生成回复                | 智能体 | 要语气恰当，不能模板填空               |

**整体思路**：智能体负责“思考做什么”，工作流负责“高效执行确定步骤”。

## 如果面试官追问：为什么不全部用智能体？

回答模板：

> 全用智能体有三个问题：
> 1. **太贵**——每次调用API都让LLM做，费用翻几百倍
> 2. **太慢**——一次决策2-5秒，高并发扛不住
> 3. **不可靠**——可能幻觉，提取错订单号、调错API
>
> 反过来全用工作流也不行，因为自然语言理解没法用if-else写。
>
> 所以**混合架构才是最优解**。

## 回答面试的标准格式（直接用）

> 总：这个任务我会拆成X个环节，确定性高的用工作流，需要推理的用智能体。
>
> 分：用表格列出每个子任务、选谁、理由。
>
> 总：智能体负责决策，工作流负责执行，两者配合。

## 加分金句（记一句就行）

> **“智能体做高层规划，工作流做底层执行。”**

或者：

> **“工作流是确定性执行，智能体是概率性推理。两者不是取代关系，是组合关系。”**
