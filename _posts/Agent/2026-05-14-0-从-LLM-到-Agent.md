# Agent 的前世今生

从 2022 年底，GPT-3 的诞生，到如今遍地开花的 Agent 应用，想要弄明白 Agent 为什么突然这么火，
到底强在哪里，又弱在哪里，需要了解 Agent 的前世今生。首先要从前 Agent 时代开始讲起，也就是 LLM 时代！

## 一、前 Agent 时代 —— LLM时代

**时间点**：2022年底-2023年中（ChatGPT爆火后、LangChain成熟前）

**认知**：这个时期，LLM 就是一个“超级强大的文字接龙模型”。它的唯一功能是输入一段文本，它逐个在这段文本
后面进行文字填充。这个能力是怎么出现的，大家应该都知道 LLM 是通过训练形成的，其实和人类很像。我们从生下来
睁眼开始，就不断地接收到外界的语言的输入和刺激，我们学到了如何表达物品，如何表达情绪，如何描述场景，以及
如何回答别人的问题。对于 LLM 的训练来说，就是把它当做一个啥也不会的婴儿，要让它学会语言，就需要不断地提供
例子，这个“例子”，就是数据集。

**训练**：这个时候的训练方法中已经有了 SFT，且数据集中包括了问答示例，所以这个时候 LLM 是能够合理的与
人类进行交互的。

**这个阶段大家在聊的都是 Prompt Engineering **，因为大家发现对于同样的一件事情，采用不同的提示词，LLM
会给出完全不同的回答，也就是说提示词的质量对 LLM 输出的影响很大。这个阶段，社区在探索的是如何通过写提示词，
克服 LLM 的一些问题，比如：

- 模型喜欢纯猜测给出结果：通过在提示词中描写思考步骤，从而让模型“一步步思考”（Chain of Thought, CoT），提高模型结果准确率
- 模型明明知道一些知识，但是不会用在答案中：通过在提示词中指定 LLM 扮演的角色，激活模型知识库中的一些知识
- 调用API的时候，很难自动化处理模型不稳定的输出：通过在提示词中要求输出JSON/Markdown格式
- 模型喜欢编造不存在的东西：通过在提示词中强调“不知道就如实输出不知道”
- 对于一些特定的任务，模型没有这个知识：在提示词中给几个问答对的例子 (Few-shot)

**代表性技术**：在验证了这些经验的有效性后，逐渐演变为提示词工程技术，如 Few-shot、Chain-of-Thought、
Self-Consistency、Role Prompting 等。见 [提示词工程](./2026-05-16_2_Prompt%20Engineering.md)

**这个阶段的局限**：

- LLM 需要什么信息，**只能人工输入**，无法让 LLM 自己去获取

## 二、Agent概念萌芽

**时间点**：2023年中-2023年底（ChatGPT Plugins、Function Calling 出现）

**前置条件**：上个时代社区摸索的一些提示词工程，可以理解为一些 LLM 应该具有的能力，而按照人类去做类比的话，
想让 LLM 拥有这些技能，做一些针对这些能力的数据集，继续去做 SFT 就行了。所以随着大模型的迭代，模型不需要 CoT，
就会在输出之间先进行一轮思考，典型的就是 Deepseek-R1，这个时候大模型也已经学会了用纯 JSON 格式来输出想要
调用的工具和参数，并根据工具结果进行下一步的输出。

**认知**：上个时代 LLM 无法自己获取信息，就算做了一个和 LLM 交互的 loop，也无法起到多大用处。在通过 SFT，
LLM 具有了一些新的能力后，Agent 成为可能

**此时的 Prompt Engineering 要解决新问题**：

- 怎么让模型决定“该不该用工具”
- 怎么让模型生成正确的函数调用参数
- 怎么处理工具返回的结果
- 怎么在多步调用之间保持状态

**代表性技术**：ReAct（Reason+Act）、Toolformer、Plan-and-Solve、

**这个阶段的本质**：

> Prompt Engineering 仍然是核心，但 prompt 不再是“给模型看”，而是“给模型一个决策框架”。

你写的 prompt 变成了：

```text
你是一个智能体，你可以使用以下工具：
- search(query)：搜索互联网
- calculate(expression)：计算数学表达式

你需要：
1. 思考当前需要什么信息
2. 选择合适的工具
3. 根据工具结果继续思考

用户问题：{question}
```

**关键词**：**决策框架、工具使用、多步推理**

### 小结：ReAct + Plan-and-Solve = 现代Agent的骨架

- **ReAct**：让LLM能“边想边做”，应对未知问题
- **Plan-and-Solve**：让LLM能“先规划后执行”，长期任务不走偏
- **两者结合**：先做Plan，执行中用ReAct，遇到意外反馈修订Plan

这个模式就是现在所有Agent框架（LangGraph、AutoGen、Claude Agent SDK）的共同底层逻辑：
> 高层做规划（Plan），低层做执行（ReAct），状态管理做衔接（记忆/文件/git）。

## 三、成熟Agent时代

**时间点**：2024年至今（Claude 3、GPT-4 Turbo、各种Agent框架成熟）

**认知转变**：

> Prompt Engineering 不再是“写一段话给模型”，而是**设计一个“决策系统”**——模型自己写 prompt 给自己，或者系统动态调整 prompt。

**这个阶段的 Prompt Engineering 形式**：

1. **Agent 自己写 prompt**：
- Agent A 拆解任务，为 Agent B 生成专用的 prompt
- 例如：主Agent说“你去查一下今天的天气”，然后动态生成一个“你是一个天气查询专家……”的 prompt 给子Agent
2. **System Prompt 变得极其复杂**：
- 不再是“你是一个助手”，而是几百行伪代码
- 包含：可用工具列表、决策树、错误处理规则、记忆读写规范
3. **Prompt 变成“可执行代码”**：
- Anthropic 的“提示工程指南”里，prompt 包含 XML 标签、条件判断、循环逻辑
- 例如：`<if condition="tool_result contains 'error'">...</if>`

**代表性技术**：

- **Meta-Prompting**：用LLM来写/优化prompt（对抗三方体：生成器→审计器→优化器）
- **Autonomous Prompt Engineering**：Agent在运行时自己发现prompt问题并自动修复
- **Prompt Optimization**：用算法（进化/搜索/元学习）自动搜索最优prompt

**本质变化**：
> 前Agent时代，人写prompt；Agent时代，系统自己写prompt。

**关键词**：**动态生成、自举、元认知**
